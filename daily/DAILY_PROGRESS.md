## 💡 经验总结

### 成功经验

1. **GitHub API 很有用**
   - 可以直接创建 Tag 和 Release
   - 不需要图形界面
   - Token 只在内存中使用

2. **纯技术内容更容易过审**
   - 掘金更倾向于技术内容
   - 推广痕迹过重容易被拒绝
   - 需要平衡技术价值和推广需求

3. **Markdown 格式很重要**
   - 需要使用正确的代码块标记
   - 链接处理要谨慎
   - 表格和列表提高可读性

### 需要注意

1. **掘金 API 路由问题**
   - API 端点可能更新了
   - 需要查阅最新文档
   - 不能依赖旧的 API 端点

2. **掘金审核机制**
   - 纯技术内容更容易过审
   - 推广痕迹过重容易被拒绝
   - 需要理解平台规范

3. **记忆系统重要性**
   - 新会话恢复需要完整的记忆
   - 知识库和技能库很重要
   - 自我迭代记录对长期成长很重要
